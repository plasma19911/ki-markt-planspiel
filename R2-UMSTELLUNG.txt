KI MARKT-PLANSPIEL – R2 UMSTELLUNG
===================================

Der Programmcode ist auf R2 als Hauptspeicher umgestellt.
Durable Objects werden im normalen Live-Betrieb nicht mehr fuer Status, Trades, History, News oder Cron-Scans benutzt.

AUTOMATISCHE R2-BEREITSTELLUNG

Die R2-Bindung wird jetzt von Wrangler automatisch bereitgestellt.
Im Repository steht nur noch:

   Binding: STATE

Ein fester Bucket-Name ist absichtlich NICHT mehr eingetragen.
Mit Wrangler >= 4.45 erstellt Cloudflare beim Deploy automatisch einen passenden R2-Bucket und bindet ihn als STATE an den Worker.
Das funktioniert auch bei Deployments aus dem Cloudflare-Dashboard/GitHub.

WAS DU JETZT TUN MUSST

1. Im Cloudflare Dashboard den Worker "ki-markt-planspiel" oeffnen.
2. Unter Deployments den neuesten GitHub-Stand abwarten bzw. den Deploy erneut starten.
3. Nach erfolgreichem Deploy die Website hart neu laden.
4. /api/status im Browser pruefen.

In der JSON-Antwort muss stehen:

   "storage": {
     "backend": "R2",
     "key": "state/current-v1.json"
   }

Wenn der Deploy noch den alten Fehler "R2-Binding STATE fehlt" zeigt, ist noch ein alter Worker-Stand aktiv. Dann den neuesten GitHub-Commit erneut deployen.

NORMALER BETRIEB DANACH

- /api/status liest den Zustand aus R2.
- Der Minuten-Cron liest/schreibt R2.
- Start, Stop, Reset und Trades schreiben R2.
- Aktien + normale ETFs bleiben aktiv.
- Hebel-/Inverse-Produkte bleiben deaktiviert.
- Das alte Durable Object ist nur noch fuer eine optionale einmalige Migration vorhanden.

OPTIONAL: ALTEN DURABLE-OBJECT-STAND UEBERNEHMEN

Sobald das alte Durable-Object-Tageslimit wieder zurueckgesetzt wurde, kann einmalig dieser API-Aufruf ausgefuehrt werden:

   POST /api/migrate-from-do

Dadurch werden der alte Depot-/History-/News-/KI-Log-Stand nach R2 kopiert.
Danach wird das Durable Object fuer den normalen Betrieb nicht mehr benoetigt.
